# ST0005: Bring the suite and dev tooling current after the Intent v3 port

## Objective

Bring Cdsync's own test suite and development tooling back into line with the repository as it stands after two changes nothing had measured: the Intent v3 port of 26 August 2026, which moved every steel thread's record into the store's committed extract, and devbin being vendored into `bin/` on 15 September 2026.

1. **The acceptance-contract guard reads the contracts where they now live.** It fails as soon as the suite runs, because the port removed every `acceptance.md` it globbed. It must read `intent/.canon/st/<id>.json`, cover every thread whether open or closed, and still fail when it can read nothing.
2. **devbin is committed without publishing anything a public repository must not carry**, and `bin/devbin test all` runs the bats suite as a sealed gate.
3. **A release still carries the tool and nothing about how the tool is made.** devbin is how it is made.
4. **The record agrees with itself.** Dead code citing a thread path that no longer exists is removed, and the hand-kept ledger matches the store.

## Context

Found at vc's pickup on 15 September 2026, the first session since the 9 August globalfold. Nothing had run the suite against the repository since the port: CI last ran on 9 August, every commit since is unpushed, and neither commit hook invokes bats. hv's run of `bats test/cdsync.bats` the same afternoon reported exactly one failure, the guard's own `[ "$total" -gt 0 ]` -- which is that assertion doing its job, turning a guard that could see nothing into a failure rather than a clean report. devbin's sealed gate, run over the same tree, sealed the same single failure.

**The trap, measured rather than predicted.** Open threads are still realised on disk (`intent/.intentfiles`), so a guard reading the realised `acceptance.md` views goes green as soon as an open thread cites one real test. With one citation added to this thread, the old guard run alone passed -- having read that citation and none of the 38 in the four closed threads. The views render the extract for open threads only; the extract is the one home.

**devbin's manifest records an absolute home path.** `devbin install` writes `# source: <absolute path>` into `bin/.devbin/manifest.sha256`, and every sibling estate checked that tracks the manifest carries the same line. That is devbin's defect to fix; this thread only has to keep it out of this repository.

## Acceptance

Acceptance Criteria and Acceptance Tests are RENDERED into `acceptance.md`, which is a GENERATED VIEW -- a row authored there is discarded by the next sync. The contract is canon in this thread's model: change a state with the `intent ac` / `intent at` verbs, and mint or reword a row in `.canon/st/ST0005.json`, then `intent sync --to-store`. This cover never restates them.
