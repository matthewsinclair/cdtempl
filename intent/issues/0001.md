## What

Two blocking false findings from `cdtempl check`, found on a real drop whose artefacts carry real CSS. Both are in `lib/scan.sh`.

1. **Rule 1 counts CSS attribute selectors as blanks.** `each_blank_in_file` skips fences, `<script>` blocks and code spans, but not `<style>` blocks. Every attribute selector in a style block, such as `[role="tab"]` or `[data-theme="dark"]`, starts with a lower-case letter and is counted as a blank, so an asset with real CSS reports `status: complete but N blanks remain`, which blocks. The drop that found it works around it by writing `[ role="tab"]`, which a browser reads as the same selector. Rule 3's `each_metric_in_file` already strips `<style>` blocks and `style="..."` attributes, so rule 1 and rule 3 disagree about what counts as prose: the shape the comments at `lib/scan.sh:175` and `lib/scan.sh:464` describe.

2. **Rule 4 reads decimal numeric character references as hex colours.** `CDTEMPL_COLOUR_RE` matches `#[0-9a-f]{3,8}\b` whatever precedes the `#`. So `&#10003;` (a check mark) is read as `#10003`, `&#8212;` (an em dash) as `#8212`, and `&#160;` (a no-break space) as `#160`, which normalises to `#116600`. None is in a kit, so each is reported as a colour absent from `kit/tokens.json`, which blocks. The hex form, `&#x2713;`, is not matched.

## Reproduction

Against `lib/scan.sh` at cdtempl 0.1.0, as the working tree stood on 2026-10-19:

```
$ cat style.html
<style>
  .tabs [role="tab"] { border: 0; }
  :root[data-theme="dark"] { color-scheme: dark; }
  .tabs [ role="tab"] { padding: 0; }
</style>
<p>Every tab is labelled.</p>
$ cat entities.html
<p>Done &#10003; and&#160;kept, &#8212; as before; hex form &#x2713; too.</p>
$ bash -c 'source <cdtempl>/lib/scan.sh; each_blank_in_file style.html; each_colour_in_file entities.html'
role="tab"
data-theme="dark"
#10003
#116600
#8212
```

A control file holding a real blank (`[venture name]`) and a real colour (`#1a2b3c`) reports both, so the scanners do see true positives.

## To do

- Rule 1: skip `<style>` blocks and `style="..."` attributes as rule 3 does, preferably through one shared definition of what is not prose, so the two scanners cannot drift apart again.
- Rule 4: drop numeric character references (`&#NNN;` and `&#xHHH;`) before the colour pattern runs. Separately, `{3,8}` admits five- and seven-digit runs, which no CSS colour has. Matching only 3, 4, 6 and 8 digits would narrow it, though on its own it would not stop `&#160;` or `&#8212;`.
